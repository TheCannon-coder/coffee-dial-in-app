# Dial In — Full App Specification
## For iOS Rebuild in Replit

---

## 1. What the App Does

Dial In is a coffee coaching app. After each brew, the user describes how their cup tasted — using tappable chips or free text — and the app returns exactly one adjustment to try next time. No jargon, no multiple suggestions, just one clear next step.

The core idea: changing too many things at once makes it impossible to know what worked. The app enforces single-adjustment discipline.

**Live web version:** https://www.coffeebrew.coach  
**Tech stack (web):** Vanilla JS / HTML frontend on Vercel, Node.js serverless API functions, Supabase (Postgres), Stripe, Anthropic Claude API (claude-haiku-4-5), Klaviyo

## 2. User Tiers

### Anonymous (no account)
- 3 free brews per month, tracked by a UUID stored on the device
- Gets brew advice but no history saved
- After 3 uses, shown an email sign-up wall
- No "Skip" button on the last free brew — email is required to continue

### Free (email only)
- 10 free brews per month
- Brew history saved and accessible across sessions
- Can earn bonus dial-ins via referrals (+2 per friend who completes their first brew)
- Monthly counter resets on the 1st of each month
- Added to Klaviyo email list on sign-up

### Pro (paid subscription)
- Unlimited brews per month
- All free features included
- Can manage/cancel subscription from within the app
- Two price options: $4.99/month or $44.99/year
- Promotion codes accepted at checkout

## 4. AI Coaching Logic

### The seven possible recommendations
The AI can only recommend one of these:
1. Grind finer
2. Grind coarser
3. Use more coffee
4. Use less coffee
5. Steep longer (AeroPress only)
6. Steep shorter (AeroPress only)
7. Leave it as-is (cup is great)

### Response format
Always exactly two sentences:
- Sentence 1: A warm opener calibrated to the ratio of good notes vs fault notes
- Sentence 2: "Let's [adjustment] next time and see if that [soft outcome]."

No jargon. No markdown. Never asks clarifying questions. Never explains reasoning.

### Opener calibration
- Cup sounds great (no faults): "This sounds wonderful :) Enjoy and let's brew this coffee the same way next time!"
- Positives clearly outnumber faults: "We're so close to the perfect brew :)" or "We're so close!"
- Roughly even mix: "All good :) Let's fix this together." or "We're getting there :)"
- Faults clearly outnumber positives: "Not ideal, but we're learning :)" or "This could definitely be better :)"

### Core decision logic
**Body signals take priority when strong:**
- 2+ low body signals (watery/weak/thin/tea-like) → "use more coffee" regardless of other signals
- 2+ high body signals (heavy/thick/muddy/sludgy) → "use less coffee" regardless of other signals
- When body AND extraction point the same direction → grind adjustment fixes both (thin + sour → grind finer; heavy + bitter → grind coarser)

**Extraction signals:**
- Sour, sharp, short finish, salty → under-extraction → grind finer
- Salty is unambiguous — always grind finer, never overridden
- Dry, astringent, chalky → over-extraction → grind coarser — always, never overridden
- Bitter alone → usually grind coarser, but deprioritised if paired with high body or multiple under-extraction signals

**AeroPress exception:**
- Steep longer/shorter are valid alternatives to grind adjustments

**Free-text interpretation:**
The app accepts non-standard descriptions in the free text field and translates them to extraction signals. Examples:
- Colour words: yellow/angular/green → under-extraction; dark/ashy/rough → over-extraction
- Shape words: round/smooth → balanced; angular/sharp → fault depending on context
- Texture words: thin/airy/watery → low body; rough/scratchy/chalky → over-extraction
- Sound words: bright/piercing → under-extraction; low/dark/heavy → over-extraction
- Full flavour family table covering 23 families (floral, berry, dried fruit, apple/pear, stone fruit, citrus, tropical, grape, honey, vanilla, caramel, cocoa, nutty, peanut, spice, cereal/malt, herbal, green/vegetal, smoky, earthy, fermented, chemical)

### Adjustment history loop prevention
The API receives the full history of prior adjustments for the same coffee. If the same adjustment has been recommended repeatedly without improvement, the AI is prompted to consider an alternative.

## 5. Brew History

Each saved coffee appears as a card on the home screen.

**Card shows:**
- Coffee name (or brew method if no name given)
- Last brew date
- Last recommended adjustment (e.g. "→ Grind finer")
- Tapping the card opens the repeat brew reminder screen

**Saved locally on device and synced via email on first sign-in.**

Each coffee also stores an `adjustmentHistory` array — a chronological list of all adjustments recommended for that coffee (used to prevent the AI looping the same recommendation).

## 7. API Endpoints

### POST `/api/dialin`
Main coaching endpoint.

**Request body:**
```json
{
  "email": "user@example.com",       // optional — omit for anonymous
  "anonId": "uuid-string",           // for anonymous users only
  "method": "V60",
  "coffee": "15",
  "water": "250",
  "brewTime": "3:00",
  "waterTemp": "93°C",
  "coffeeName": "Ethiopian Yirgacheffe",
  "grinderNotes": "Setting 14",
  "tastingNotes": "Sour, Sharp, Watery",
  "freeNotes": "tasted angular and yellow",
  "adjustmentHistory": ["grind_finer", "grind_finer"],
  "ref": "REFERRAL_CODE"
}
```

**Logic flow:**
1. Build coaching prompt from all inputs
2. If no email → anonymous path: check/enforce 3/month limit by anonId, call AI, return advice
3. If email provided → look up or create user record
4. Reset monthly counter if new calendar month
5. Award referral bonus if new user with referral code (+2 to referrer's monthly limit)
6. Check usage limit (skip if Pro)
7. Call Anthropic API (claude-haiku-4-5, max 120 tokens)
8. Increment usage counter
9. Add new user to Klaviyo list
10. Save brew to `brews` table
11. Return advice + adjustment key + usesRemaining + isPro

**Possible adjustment keys returned:** `grind_finer`, `grind_coarser`, `more_coffee`, `less_coffee`, `steep_longer`, `steep_shorter`, `none`

**Response (success):**
```json
{
  "advice": "We're so close! Let's grind a little finer next time and see if that rounds things out.",
  "adjustment": "grind_finer",
  "usesRemaining": 7,
  "isPro": false
}
```

**Response (limit reached — free user):**
```json
{
  "error": "limit_reached",
  "resetsOn": "2026-07-01"
}
```

**Response (limit reached — anonymous):**
```json
{
  "error": "limit_reached",
  "resetsOn": "2026-07-01",
  "requiresEmail": true
}
```

### POST `/api/create-checkout`
Creates a Stripe Checkout session for upgrading to Pro.

**Request body:**
```json
{ "email": "user@example.com", "plan": "yearly" }
```
`plan` is either `"yearly"` or `"monthly"`

**Response:**
```json
{ "url": "https://checkout.stripe.com/..." }
```

The client redirects to this URL. After payment, Stripe redirects back to `https://www.coffeebrew.coach?upgraded=1`

Promotion codes are accepted (`allow_promotion_codes: true`)

---

### POST `/api/stripe-webhook`
Receives Stripe webhook events. Verifies signature with `STRIPE_WEBHOOK_SECRET`.

**Handled events:**
- `checkout.session.completed` → sets `is_pro = true`, saves `stripe_customer_id` and `stripe_subscription_id`
- `customer.subscription.deleted` → sets `is_pro = false`, clears subscription ID
- `invoice.payment_failed` → logged only; Stripe handles retries

---

### POST `/api/customer-portal`

## 8. Referral System

- Every signed-in user has a unique referral code
- Referral link format: `https://www.coffeebrew.coach?ref=CODE`
- When a new user signs up via a referral link and completes their first brew, the referrer gets +2 added to their monthly limit
- The referral card on the home screen shows the user's link with Copy, Email, and Text share buttons
- Email share: opens mail client with pre-written subject and body
- SMS share: opens SMS app with pre-written message

---

## 9. Subscription Management

- "Manage subscription" link appears on the home screen for all signed-in users
- Tapping it calls `/api/customer-portal` → redirects to Stripe's hosted portal
- From the portal, users can: view plan, update payment method, cancel subscription
- On cancellation, the Stripe webhook fires `customer.subscription.deleted` → `is_pro` is set to false in the database
- If no subscription is found, the app shows an alert: "No active subscription found for this account"

## 13. Key Behaviours and Edge Cases

- **Monthly reset:** On every API call, if the current month differs from `month_reset_at`, the usage counter is reset to 0 and the limit is restored to 10 before the limit check runs
- **Repeat brew flow:** Tapping a saved coffee card shows the last recommendation and pre-fills the brew setup form with saved settings — makes it easy to try the recommended adjustment
- **Adjustment history:** Each saved coffee stores a list of all adjustments received. This is passed to the AI so it can avoid looping the same suggestion if previous adjustments haven't helped
- **"Upgraded" return:** When Stripe redirects back with `?upgraded=1`, the app shows a success banner and reloads the user's Pro status
- **No password:** Authentication is email-only. The email acts as a persistent identifier. There is no password, OAuth, or session token — just an email stored in localStorage
- **Cross-device:** Brew history is tied to email. If a user signs in with the same email on a new device, their history is fetched from the server
- **Brew timer:** The built-in timer auto-fills the brew time field. The "Use time" button appears only after the timer has been started and stopped
- **Anonymous UUID:** Generated with `crypto.randomUUID()` on first brew attempt, stored in localStorage as `dialin_anon_id`. Passed to the server as `anonId`. If the user later enters their email, they transition to a tracked free account

## 14. What the iOS App Should Replicate

**Core flows to build:**
1. Onboarding with email capture
2. Home screen with saved coffees list and referral card
3. Brew setup form (all fields, brew timer)
4. Tasting chip selection screen
5. AI result display with save/skip prompt for anonymous users

**Local storage equivalents needed in iOS:**
- `dialin_email` → UserDefaults or Keychain
- `dialin_anon_id` → UserDefaults
- `dialin_saved_coffees` → UserDefaults or CoreData (JSON array of brew objects)
- `dialin_ref` → UserDefaults (referral code from deep link)
- `dialin_is_pro` → UserDefaults (cached Pro status; source of truth is the server)
